### 🎉 Смена механизма: dnsmasq-ipset вместо автообучения (learn-everything)

**Корень проблемы v3.12:** автообучение добавляло в `bypass_nets` ЛЮБОЙ исходящий IP на 80/443/UDP-443 без проверки блокировки, и `restore_learned()` персистил выученное (накопление монотонное) → «обычные» сайты (2ip.ru, yandex) уходили в WARP.

### Изменено (архитектурно)
- **Автообучение по dmesg/LOG УДАЛЕНО** (учило всё подряд). Вместо него — **dnsmasq-native ipset**: при резолве домена из блок-листа dnsmasq сам кладёт его IP в `bypass_nets` (`ipset=/…/bypass_nets`). Нагрузка ~0 (штатный DNS), точность по домену, стабильность.
- **Доменный список:** `itdoginfo/allow-domains` (Russia inside) — сервисные и медийные домены платформ (YouTube/Discord/Meta/Twitter/TikTok и др.). Авто-обновление в `ipset_update.sh` (каждые 6 ч), идемпотентная вставка в `dnsmasq.conf` по маркерам.
- **Удалены:** LOG-правила `PWB_LEARN`, learning-цикл watchdog, `restore_learned()`, кэш `learned_ips.cache`.

### Исправлено
- **Источники CIDR (D/E):** битый путь `1andrevich/…/cidr.txt` (404) → `ipsum.lst`; мёртвый `runetfreedom/text/ru-blocked.txt` (только бинарные .dat) → `community.antifilter.download/community.lst`; малый `antifilter subnet.lst` (70) → `allyouneed.lst` (18 261). Итого 12 источников, все — чистый CIDR.
- **Чистка накопленного (C):** при установке сбрасывается `learned_ips.cache`; `ipset` перестраивается из CIDR (`swap`).
- **`rollback.sh` / `uninstall.sh`:** корректная очистка блока dnsmasq из конфига; `selftest.sh` теперь проверяет dnsmasq-ipset и загрузку CIDR.
- **Локальный `selftest.sh`:** встраивается в `/etc/storage` (было: только через curl); README согласован.
- **Рассинхрон диагностики (rc1 → rc2):** отдельные `selftest.sh`/`diagnostic.sh`/`TESTING.md`/`restore_test.sh` не попали в rc1 (устаревшие ссылки на `PWB_LEARN`/`restore_learned`). Исправлены под dnsmasq-механизм. В `make test` добавлен cross-ref гейт (`consistency`), который валит сборку при устаревших ссылках в продаваемых скриптах.

### Не берём (осознанно)
- `antifilter ipresolve.lst` (154 198, per-IP) — тяжёлый для CPU/RAM роутера.

### Изменено
- Версия: `3.12.0-beta` → `3.13.0-beta`. Рабочая ветка — `feature/phase4-autolearn`.

## [3.12.0-beta] - 2026-10-08

### 🎉 Расширенное автообучение: TCP 80/443 + UDP/QUIC 443

**Переработан механизм автообучения адресов в `route_watchdog.sh` + сопутствующие файлы.**

### Добавлено
- **Явное `iptables -j LOG`-правило** (`--log-prefix "PWB_LEARN "`) вместо опоры на неявные `DPT=443.*SYN`-строки из dmesg (их источник вне репозитория; если прошивка их не пишет — обучение молча мертво). `-j LOG` не терминирующий — пакет идёт дальше, маршрутизация не ломается; обязательный `--limit 30/min --limit-burst 60` защищает слабый CPU и dmesg-ring роутера.
- **Учёт UDP 443 (QUIC):** обучаемся также на QUIC-трафике (медиа Telegram, стриминг YouTube) — раньше только TCP.
- **Расширенные порты:** TCP `80` + `443` (раньше только 443 SYN).
- **Парсинг только своих строк:** фильтр по префиксу `PWB_LEARN` вместо «любых DPT=443», с дедупом по пакету (`sort -u`).

### Исправлено
- **wg0-шум в загрузочном логе:** watchdog при отсутствии `wg0` (ранняя загрузка) писал `Cannot find device "wg0"` и `can.t create .../wg0/rp_filter`. Теперь wg0-операции (маршрут table 51 + rp_filter) обёрнуты в `ip link show wg0`-guard (пропуск, одноразовый лог, без спама); rp_filter — доп. `[ -f ]`-guard (фикс утечки stderr). Проверено функц. тестом (`wg0_guard_test.sh`, 7/7 OK).
- **Выученные IP не восстанавливались после перезагрузки (регрессия v3.12):** `restore_learned()` использовал `done < "$(sort -u FILE)"` — это открывает файл с именем-выводом `sort` вместо stdin. Ошибка `can't open <ip> …: no such file`, count=0. Исправлено: дедуп в `$LEARNED_CACHE.dedup`, затем чтение из него.
- **LOG-правила не встают при переустановке (критично):** старый инстанс watchdog удерживал lock `/tmp/route_watchdog.lock` → новый инстанс выходил молча, и его правки (LOG) не применялись (MARK/CONNMARK жили за счёт старого). `install.sh` теперь делает `killall route_watchdog.sh` + сброс lock перед запуском.
- **LOG-правила стали идемпотентными и само-восстанавливаются:** блок LOG перенесён ВНУТРЬ цикла (как MARK/CONNMARK) — не зависит от порядка запуска относительно создания ipset `bypass_nets` и восстанавливается каждые 15 с.
- **Ошибки вставки LOG больше не глушатся молча:** при сбое — `stderr` в `/tmp/route_watchdog.log` + **fallback** на раздельные TCP-правила (80 и 443), если `-m multiport` недоступен.
- **`-m set` O(1):** LOG-правила матчат кандидатов через `! --match-set bypass_nets dst` (хэш-таблица), а не через `! -m set … -m multiport` — без деградации на горячем пути.
- **Дедуп кэша обучения:** `restore_learned()` теперь читает `sort -u` (BusyBox-совместимо), кэш не растёт дублями.
- **Обрезка кэша:** `learned_ips.cache` ограничен `LEARNED_MAX=2000` записей (обрезаем хвост).
- **Чистое удаление:** `uninstall.sh` удаляет новые LOG-правила и сбрасывает счётчик.
- **Диагностика:** `diagnostic.sh` проверяет наличие LOG-правил `PWB_LEARN`.

### Изменено
- Версия: `3.11.0-beta` → `3.12.0-beta` (`install.sh` ×3, README badge, CHANGELOG).

## [3.11.0-beta] - 2026-10-08

### 🎉 Устойчивость автосборки: защита от дублей и гонок

**Исправления надёжности в `install.sh`, `route_watchdog.sh`, `uninstall.sh`, `diagnostic.sh`.**

### Исправлено
- **Дубли Cron при переустановке:** очистка теперь удаляет и `ipset_update.sh`, и `route_watchdog.sh` (раньше — только первый; на роутере скапливалось до 5 записей `@reboot`).
- **Гонки watchdog:** добавлен lock-файл `/tmp/route_watchdog.lock` — исключает запуск нескольких копий.
- **Конфликт с `vpnc_wireguard`:** правило CONNMARK restore теперь применяется только к пакетам не из `wg0` (`! -i wg0`) — устраняет петлю со встроенной цепочкой прошивки.
- **Cron, выключенный в веб-морде:** принудительное включение (`crond_enable=1` в NVRAM + старт в `started_script.sh`).
- **Запуск при загрузке:** `started_script.sh` зарегистрирован в NVRAM boot script (`script_aft_net_start`).
- **Чистое удаление:** `uninstall.sh` синхронизирован — удаляет `started_script.sh`, lock-файлы, cron-строки `route_watchdog.sh`, сбрасывает `script_aft_net_start` (переменную `crond_enable` НЕ трогает).
- **Диагностика:** `diagnostic.sh` — fallback-проверка CONNMARK restore (новый синтаксис → старый).

### Изменено
- README: возвращена секция «Проверка совместимости» (`hardware_check.sh`); требование VPN — **AmneziaWG или WireGuard**.
- Версия: `3.10.9-beta` → `3.11.0-beta`.

## [3.10.9-beta] - 2026-04-24

### 🎉 Финальная бета-версия с полной поддержкой IPv6

**Добавлена поддержка IPv6, улучшена проверка WAN, исправлена логика восстановления ipset6.**

### Добавлено
- **Полная поддержка IPv6:** создание `bypass_nets6`, правила `ip6tables` (MARK и CONNMARK), policy routing для IPv6.
- **4 источника CIDR для IPv6** (Telegram, Facebook, Google, Cloudflare).
- **Двойная проверка WAN** (`ping 8.8.8.8` + `wget --spider http://cp.cloudflare.com`) для максимальной надёжности.
- **Проверка наполненности ipset6** после быстрого восстановления: если записей меньше 10, запускается полное обновление IPv6.
- В watchdog добавлена страховка создания `ipset6` (если основной скрипт ещё не запускался).

### Исправлено
- Устранено ложное срабатывание «ipset6 пуст» (заменён grep на точный подсчёт записей через `Number of entries`).
- В автозагрузку добавлена загрузка модуля `ip6_set_hash_net`.
- В `uninstall.sh` добавлено удаление IPv6-компонентов (правила `ip6tables`, `bypass_nets6`, CIDR-файлы).

### Производительность
- Охват IPv4: **66 000+ подсетей** (миллионы IP-адресов).
- Охват IPv6: **75+ подсетей** (Telegram, Google, Cloudflare, Meta).
- Быстрое восстановление после перезагрузки: **5–10 секунд**.
- Полное обновление: **2–3 минуты** (раз в 6 часов).

## [3.10.9-beta] - 2026-04-23

### 🎉 Стабильная бета-версия с новой архитектурой

**Полный переход на CIDR-списки, быстрое восстановление, проверка handshake.**

### Добавлено
- **13 источников готовых CIDR-списков** (подсетей) от проверенных проектов.
- **Быстрое восстановление ipset** из локального CIDR-файла (5–10 секунд после перезагрузки).
- **Проверка готовности VPN** через `awg show handshake` (надёжнее, чем `curl`).
- **Ожидание WAN** через `wget --spider` (гарантирует доступность HTTP/DNS).
- Сохранение и загрузка выученных IP (`learned_ips.cache`).
- Watchdog с автообучением (анализ `dmesg`).

### Изменено
- **Удалена** зависимость от доменных списков и резолва через `nslookup`.
- **Упрощена** логика обновления: больше нет кэша доменов и хешей источников.
- **Увеличены таймауты** ожидания сети до 120 секунд для медленных handshake.
- **Оптимизирована** автозагрузка: задержки 60 и 90 секунд.

### Исправлено
- Ошибка `Set bypass_nets doesn't exist` при добавлении правил iptables.
- Проблема с `grep -oP` в BusyBox (заменено на POSIX-совместимые выражения).
- Зависание скрипта при отсутствии интернета на старте.
- Неполное сохранение дампа `ipset save` (теперь сохраняется исходный CIDR-файл).

### Производительность
- Охват: **66 000+ подсетей** (миллионы IP).
- Восстановление после перезагрузки: **5–10 секунд**.
- Полное обновление: **2–3 минуты** (раз в 6 часов).

## [3.8.1] - 2026-04-21

## [3.8] - 2026-04-21

### Добавлено
- **Автообучение watchdog:** каждые 60 секунд анализируется `dmesg` на предмет неудачных SYN-пакетов к порту 443. IP-адреса назначения автоматически добавляются в `bypass_domains`. Позволяет открывать сайты, блокируемые провайдером путём сброса TCP-соединения (TCP Reset).
- Исправлено регулярное выражение для поиска записей в `dmesg`: теперь поддерживается любой порядок полей `DPT=443` и `SYN`.

### Изменено
- Увеличен интервал анализа автообучения до 60 секунд (переменная `ANALYZE_INTERVAL`).
- Обновлены комментарии и номер версии во всех скриптах.

## [3.7-beta] - 2026-04-19

### Добавлено
- **Поддержка IPv6:** создаётся отдельный ipset `bypass_domains6`, настраиваются `ip6tables` и policy routing для IPv6. Трафик IPv6 к сайтам из списков направляется через туннель WARP.
- **Правила CONNMARK:** добавлены правила `iptables` для сохранения метки `0xca6c` в conntrack и её восстановления для ответных пакетов. Улучшает стабильность соединений для сервисов, чувствительных к потере маршрута.
- **Автовосстановление ipset в watchdog:** если количество записей в `bypass_domains` падает ниже 100, watchdog автоматически запускает `ipset_update.sh`.
- Расширенные проверки в watchdog: добавлен контроль правил CONNMARK, ip6tables и IPv6 policy routing.
