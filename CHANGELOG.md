## [3.16.1-beta] - 2026-10-26

### 🐞 fix(webui): страница открывалась пустой — установка не разворачивала её в слот

**Симптом:** `http://<router>/custom/index.html` открывался, но показывал
пустое белое поле.

**Причина:** `install.sh` создавал мастер-копию страницы и скрипт
`pwb_web_setup.sh`, но **никогда не вызывал `stage`**. Развёртывание в
`/opt/share/www/custom/index.html` выполнялось только в boot-хуке, то есть
исключительно при перезагрузке роутера. Сразу после установки `/opt`
оставался read-only, каталог `custom` не создавался, симлинк
`/www/custom` указывал в пустоту — httpd отдавал пустой ответ.

**Исправлено:**
- `install.sh`: вызов `/etc/storage/pwb_web_setup.sh stage` при установке.
  Строго **после** создания `started_script.sh` — иначе boot-хук некуда
  записать (эта ошибка порядка была допущена и исправлена в процессе).
- `pwb_web_setup.sh`: проверка монтирования `/opt` теперь `/proc/mounts`
  **или** доступность записи в `/opt` — на части прошивок строка
  монтирования выглядит иначе.
- `Makefile`: регресс-тест `webstage` — проверяет, что `stage` вызывается
  и что он идёт **после** `started_script.sh`.
- `scripts/check-heredoc-sync.sh`: добавлен контроль синхронизации для
  `pwb_web_setup.sh`.

**Доказательство (симуляция с подменой путей):** до фикса `runtime=absent`;
после — `stage rc=0`, `runtime=present`, `boothook=present`, содержимое
файла соответствует мастер-копии.

## [3.16.0-beta] - 2026-10-26

### 🌐 Веб-страница «Домены в туннель»

Пользователь открывает страницу в родном WebUI роутера, вводит домен — и сайт
начинает ходить через туннель. Без SSH, без правки конфигов, без второго сервера.
Список переживает перезагрузку. Работает и по IPv4, и по IPv6.

**Как это устроено:**

```
http://<router>/custom/index.html
   → POST /apply.cgi (SystemCmd) — штатный механизм прошивки, как у «Консоли»
   → /etc/storage/bypass_domains.sh add <домен>
       1. валидация домена (анти-инъекция)
       2. запись в /etc/storage/bypass_domains.lst
       3. перегенерация маркерного блока в dnsmasq.conf:
          ipset=/домен/bypass_nets,bypass_nets6
       4. ПОЛНЫЙ рестарт dnsmasq (HUP не применяет конфиг)
       5. резолв домена → IP сразу попадает в наборы
       6. mtd_storage.sh save
```

**Новые файлы:**
- `bypass_domains.sh` — менеджер доменов: `add`, `del`, `list`, `apply`, `status`.
  Строгая валидация ввода в скрипте (JS — только для подсказок, не защита).
- `web/bypass.html` — страница: самодостаточный HTML, без внешних CDN,
  мобильный вид, список с удалением, журнал операции.
- `pwb_web_setup.sh` — разворачивание страницы в штатный слот прошивки.

**Врезка (проверено на живом устройстве 2026-10-10):**
`/www` — read-only squashfs, но прошивка содержит симлинк
`/www/custom → /opt/share/www/custom`. `/opt` тоже read-only, однако `mount`
разрешён: tmpfs поверх `/opt` оживляет слот. `http://<router>/custom/index.html`
отдаёт страницу.

**Персистентность:** `/opt` — tmpfs, при перезагрузке всё теряется. Boot-хук в
`started_script.sh` **монтирует tmpfs заново** (проверка по `/proc/mounts`),
затем раскладывает страницу. Без этого после reboot слот пуст.

**Обвязка:**
- `uninstall.sh`: удаляет менеджер, список, страницу и мастер-копии; снимает
  блок доменов из dnsmasq и применяет полным рестартом.
- `selftest.sh`, `diagnostic.sh` (+ встроенные копии): проверки наличия менеджера,
  мастер-копии, развёрнутой страницы и boot-хука.
- `scripts/check-heredoc-sync.sh` + `Makefile`: регресс-тест — встроенные в
  `install.sh` копии обязаны совпадать с отдельными файлами. Проверен
  негативным тестом (`rc=1` при расхождении). Этот дефект случался дважды.

## [3.15.4-beta] - 2026-10-26

### 🐞 fix(diagnostic): переменные наборов не были определены во встроенной копии

Найдено на живом роутере сразу после 3.15.3-beta. IPv6-обход уже работал
(`[OK] IPv6-обход РАБОТАЕТ (10minutemail.com → ... в bypass_nets6)`),
но диагностика печатала:

    [FAIL] IPv6-набор  отсутствует — IPv6-адреса не пойдут в туннель

**Причина:** `IPSET_NAME`/`IPSET6_NAME` определены на верхнем уровне
`install.sh`, а встроенный heredoc объявлен как `<< 'EOF_DIAG'` — кавычки
блокируют подстановку переменных. В установленный `diagnostic.sh` попадал
литерал `$IPSET6_NAME`, который внутри самого скрипта не определён → пустое
имя набора → ложный FAIL (и ненулевой код возврата диагностики).

**Исправлено:**
- `install.sh`: определения добавлены внутрь встроенной копии `diagnostic.sh`.
- `scripts/check-heredoc-vars.sh` + `Makefile`: регресс-тест, который
  проверяет, что переменные, используемые во встроенных heredoc, определены
  **внутри** них. Проверен негативным тестом: при удалении определения
  скрипт падает с `rc=1`.

**Подтверждено на устройстве:** чистый тест без маскировки CIDR —
`ipset flush bypass_nets6`, домен в конфиг, полный рестарт dnsmasq,
`nslookup ipv6.google.com` → AAAA `2a00:1450:4010:c22::64` →
`is in set bypass_nets6`. IPv6-обход работает.

## [3.15.3-beta] - 2026-10-26

### 🌐 fix(ipv6): домены уходили в туннель только по IPv4 — AAAA-адреса терялись

**Проблема для пользователя:** у кого провайдер даёт IPv6, сайт из списка
открывался по IPv6 **напрямую, мимо туннеля** — и оставался заблокированным.
IPv4-обход при этом работал, что маскировало дефект.

**Причина:** конфиг dnsmasq генерировался как `ipset=/домен/bypass_nets`
(только IPv4-набор). IPv6-адрес нельзя положить в набор `family inet` —
dnsmasq его отбрасывает. Второй набор `bypass_nets6` существовал, но
в конфиге не упоминался.

**Доказано на живом роутере:** `ipset flush bypass_nets6` → адрес
`NOT in set`; домен добавлен в конфиг; dnsmasq полностью перезапущен;
`nslookup ipv6.google.com` → AAAA `2a00:1450:4010:c1c::8b` → снова
`NOT in set`. (Предыдущие тесты были замаскированы: адрес попадал в
CIDR-список, а не через dnsmasq.)

**Исправлено:**
- `install.sh`: генерация `ipset=/домен/bypass_nets,bypass_nets6` —
  dnsmasq сам раскладывает адреса по семействам.
- `install.sh`: перед рестартом dnsmasq гарантируется существование обоих
  наборов (иначе адреса молча теряются).
- `install.sh`, `diagnostic.sh`: убран `modprobe ip6_set_hash_net` —
  **такого модуля не существует**; IPv6-наборы обслуживает `ip_set_hash_net`
  с `family inet6`. Ложное предупреждение «IPv6 не будет работать» удалено
  вместе с советом «можно игнорировать».
- `diagnostic.sh` и встроенный selftest: вместо проверки имени модуля —
  проверка реального набора и его наполнения.
- `selftest.sh` и встроенный selftest: новая проверка IPv6-пути
  (AAAA → `bypass_nets6`), рядом с IPv4.
- `Makefile`: регресс-тесты на dual-set, отсутствие выдуманного модуля,
  гарантию создания наборов и отсутствие ложного совета.

**Совместимость:** IPv4-путь не изменён — первый набор тот же.

**3. Makefile:** встроенный `diagnostic.sh` добавлен в проверку heredoc.

## [3.15.1-beta] - 2026-10-26

### 🐞 fix(dnsmasq): полный рестарт вместо SIGHUP — конфиг применялся только после ребута

**Симптом:** домены из списка не уходили в WARP; `ipset test` показывал `NOT in set`,
хотя строка `ipset=/домен/bypass_nets` присутствовала в `dnsmasq.conf`.
Обход работал только сразу после перезагрузки роутера, затем «отваливался».

**Причина:** `killall -HUP dnsmasq` **не перечитывает конфигурационный файл**.
По семантике dnsmasq SIGHUP обрабатывает только `/etc/hosts` и сбрасывает кэш;
конфиг читается лишь при старте демона. `setup_dnsmasq()` применял доменный
список через HUP → изменения **не вступали в силу** до перезагрузки.

**Доказательство (на живом устройстве):**
- `address=/pwb-hup-test.invalid/127.0.0.1` → после HUP: `can't resolve`;
  после полного рестарта: `127.0.0.1`.
- `ipset del <IP>` → `NOT in set`; `nslookup awgconfig.com` →
  `ipset test` → `is in set bypass_nets`.

**Исправлено:**
- `install.sh`: `setup_dnsmasq()` — полный рестарт с ожиданием готовности
  (`pidof` + таймаут 10 с) вместо SIGHUP; при неудаче — ошибка в лог и `return 1`.
- `install.sh`: встроенный `rollback.sh` — тот же рестарт (откат реально откатывает).
- `uninstall.sh`: удаление блока + полный рестарт вместо HUP.
- `selftest.sh` и `diagnostic.sh`: проверка **эффекта** (резолв → `ipset test`)
  вместо проверки наличия строки — теперь ловят этот класс ошибок сразу.
- `install.sh`: убран фолбэк на нечитаемый `/etc/storage/dnsmasq.conf`;
  добавлены `mkdir -p` каталога и проверка доступности записи.

**Ограничение:** каждый прогон даёт ~2–4 с простоя DNS вместо мгновенного HUP.
Для cron-обновления раз в 6 часов это приемлемо.

## [3.15.0-beta] - 2026-10-09

### 🎯 blocked-only автообучение (безопасное возвращение автообучения)
- Вернули автообучение в безопасной форме: IP попадает в `bypass_nets` (→ WARP)
  **только если прямое соединение недоступно (заблокировано)**. Доступные сайты

  `ipset add` только для заблокированных; persist в `/etc/storage/blocked_ips.cache`
  и восстановление из него после пересборки ipset.
- `install.sh`: константы `PROBE_TIMEOUT=2`, `PROBE_INTERVAL=60`,
  `PROBE_MAX_CYCLE=8`, `PROBE_CACHE`. `setup_dnsmasq` не затронут.
- `uninstall.sh`: снятие LOG-правил `PWB_PROBE`, удаление `blocked_ips.cache`.
- `diagnostic.sh` / `selftest.sh`: проверки наличия LOG-правил `PWB_PROBE`
  и размера blocked-only кэша.
- ⚠️ Ограничение: IP-проба ловит IP-блок/null-route/отказ сети, но **не**
  SNI/TLS-only блок (при открытом TCP 443). Такие домены требуют domain-probe —
  запланировано.

- **`rollback.sh` / `uninstall.sh`:** корректная очистка блока dnsmasq из конфига; `selftest.sh` теперь проверяет dnsmasq-ipset и загрузку CIDR.

## [3.12.0-beta] - 2026-10-08

### 🎉 Расширенное автообучение: TCP 80/443 + UDP/QUIC 443

**Переработан механизм автообучения адресов в `route_watchdog.sh` + сопутствующие файлы.**

### Добавлено
- **Явное `iptables -j LOG`-правило** (`--log-prefix "PWB_LEARN "`) вместо опоры на неявные `DPT=443.*SYN`-строки из dmesg (их источник вне репозитория; если прошивка их не пишет — обучение молча мертво). `-j LOG` не терминирующий — пакет идёт дальше, маршрутизация не ломается; обязательный `--limit 30/min --limit-burst 60` защищает слабый CPU и dmesg-ring роутера.
- **Учёт UDP 443 (QUIC):** обучаемся также на QUIC-трафике (медиа Telegram, стриминг YouTube) — раньше только TCP.
- **Расширенные порты:** TCP `80` + `443` (раньше только 443 SYN).
- **Парсинг только своих строк:** фильтр по префиксу `PWB_LEARN` вместо «любых DPT=443», с дедупом по пакету (`sort -u`).

### Исправлено
- **wg0-шум в загрузочном логе:** watchdog при отсутствии `wg0` (ранняя загрузка) писал `Cannot find device "wg0"` и `can.t create .../wg0/rp_filter`. Теперь wg0-операции (маршрут table 51 + rp_filter) обёрнуты в `ip link show wg0`-guard (пропуск, одноразовый лог, без спама); rp_filter — доп. `[ -f ]`-guard (фикс утечки stderr). Проверено функц. тестом (`wg0_guard_test.sh`, 7/7 OK).
- **Выученные IP не восстанавливались после перезагрузки (регрессия v3.12):** `restore_learned()` использовал `done < "$(sort -u FILE)"` — это открывает файл с именем-выводом `sort` вместо stdin. Ошибка `can't open <ip> …: no such file`, count=0. Исправлено: дедуп в `$LEARNED_CACHE.dedup`, затем чтение из него.
- **LOG-правила не встают при переустановке (критично):** старый инстанс watchdog удерживал lock `/tmp/route_watchdog.lock` → новый инстанс выходил молча, и его правки (LOG) не применялись (MARK/CONNMARK жили за счёт старого). `install.sh` теперь делает `killall route_watchdog.sh` + сброс lock перед запуском.
- **LOG-правила стали идемпотентными и само-восстанавливаются:** блок LOG перенесён ВНУТРЬ цикла (как MARK/CONNMARK) — не зависит от порядка запуска относительно создания ipset `bypass_nets` и восстанавливается каждые 15 с.
- **Ошибки вставки LOG больше не глушатся молча:** при сбое — `stderr` в `/tmp/route_watchdog.log` + **fallback** на раздельные TCP-правила (80 и 443), если `-m multiport` недоступен.
- **`-m set` O(1):** LOG-правила матчат кандидатов через `! --match-set bypass_nets dst` (хэш-таблица), а не через `! -m set … -m multiport` — без деградации на горячем пути.
- **Дедуп кэша обучения:** `restore_learned()` теперь читает `sort -u` (BusyBox-совместимо), кэш не растёт дублями.
- **Обрезка кэша:** `learned_ips.cache` ограничен `LEARNED_MAX=2000` записей (обрезаем хвост).
- **Чистое удаление:** `uninstall.sh` удаляет новые LOG-правила и сбрасывает счётчик.
- **Диагностика:** `diagnostic.sh` проверяет наличие LOG-правил `PWB_LEARN`.

### Изменено
- Версия: `3.11.0-beta` → `3.12.0-beta` (`install.sh` ×3, README badge, CHANGELOG).
